# 「语法错误」定位排查指南（2026-10-12）

日期：2026-10-12
适用：目标 CAD 加载 `output/gb2312/one-click-simsun.lsp` 报「语法错误」

## 1 已确认的事实（开发侧）

| 项 | 结论 | 证据 |
| --- | --- | --- |
| 交付文件身份 | 就是最新构建 | SHA-256 `83a294dc…`，与构建记录一致；重新构建复现同一 SHA |
| 编码 | 严格 GB2312、无 BOM、字节全部在 A1–FE 合法区间 | 严格解码往返通过；无 UTF-8 BOM、无 0x00/0x1A 控制字节 |
| 行尾 | 纯 LF（2424 个 LF、0 个 CRLF） | 字节统计 |
| LISP 结构 | 括号配对、字符串闭合、注释完整，标准读入规则下零错误 | `tools/lisp_reader_probe.py`（模拟 AutoLISP 读入器）对全文件 0 错误 0 警告 |
| 目标引擎 | **不是标准 AutoLISP**：此前 `defmacro` 参数表被当普通调用求值（`no function definition: FN`），可证明该引擎没有把 `defmacro` 当特殊形式 | 上一次报错记录 |

结论：文件对标准规则完全干净，报错只能来自**目标引擎独有的读入器/求值器限制**。中望官方 FAQ 显示 ZWCAD Classic 的 LISP 为 "LISP Release 1.0" 精简引擎且与完整版行为不同——与本项目现象吻合，但未最终证实。不要再改编码或盲目猜语法，用下面的探针把引擎的真实限制测出来。

### 3.1 消除「未签名的可执行文件」弹窗

SECURELOAD=1 时，诊断驱动嵌套加载的 27 个文件（13 探针 + 12 部件 + 2 个主文件变体）每个都会弹安全确认框。两种解法：

**方法一（推荐，跑完即恢复）：** 加载诊断文件之前，命令行先执行：

```lisp
(setvar "SECURELOAD" 0)
```

然后照常 LOAD `ocs-diag-all.lsp`，全程无弹窗。诊断跑完后恢复：

```lisp
(setvar "SECURELOAD" 1)
```

**方法二（持久，只信任本项目目录）：** 命令行执行 `TRUSTEDPATHS`，把以下 4 个目录加入受信任位置：

```
H:\coding\一键改宋体\One-click-Song-style\output\gb2312
H:\coding\一键改宋体\One-click-Song-style\output\gb2312\probe
H:\coding\一键改宋体\One-click-Song-style\output\gb2312\parts
H:\coding\一键改宋体\One-click-Song-style\output\gb2312\crlf
```

注意：本项目的交付工具 YJST 按约定不会改动 SECURELOAD 等系统变量；以上均为手动诊断操作，与方法一用完即恢复。

## 3 备用：分步执行（旧方法，结果相同）

有的引擎按 CRLF 断行/断注释，LF 文件会被整体当成一行。先试 CRLF 变体：

```lisp
(LOAD "H:/coding/一键改宋体/One-click-Song-style/output/gb2312/crlf/one-click-simsun.lsp")
```

- 加载成功（出现"一键统一宋体（YJST）v0.1.0 已加载"）→ 行尾就是根因，后续交付固定用 CRLF。
- 仍报「语法错误」→ 行尾不是根因，继续第 3 步。

## 3 第二步：引擎特性探针（一条命令）

加载驱动并执行：

```lisp
(LOAD "H:/coding/一键改宋体/One-click-Song-style/output/gb2312/ocs-probe.lsp")
OCS_PROBE
```

驱动会依次加载 `probe/p01..p13.lsp`，每个探针只测一项语法特性，成功时打印 `PROBE-nn-OK`。输出形如：

```
== PROBE 1/13 == PROBE-01-OK basic-defun-princ ok
== PROBE 2/13 == PROBE-02-OK comment-parens-quotes ok
== PROBE 3/13 == <<< LOAD FAILED        ← 引擎不支持字符串转义
```

对照表：

| 探针 | 测试特性 | 若失败，主文件的修法 |
| --- | --- | --- |
| p01 | 基础 defun/princ/中文注释 | 环境问题（SECURELOAD/受信任位置/路径），先解决加载通道 |
| p02 | 注释内含 ASCII 括号与引号 | 主源码注释中的 `(fn &rest args)`、`"..."` 改为全角或删除 |
| p03 | 字符串转义 `\\` `\"` `\n` `\t` | 全部字符串去掉反斜杠：路径用正斜杠 `/`；测试串 C06/C15 去掉转义引号 |
| p04 | 关键字符号 `:error` | plist 键从 `:xxx` 改为字符串 `"xxx"`（assoc 行为相同），机械替换 |
| p05 | quote 简写 `'sym` | `'sym` 全部改为 `(quote sym)`，机械替换 |
| p06 | 科学计数法 `1e-9` | 改为 `(/ 1.0 1000000000.0)` |
| p07 | 16 层深层嵌套 | 拆函数降低嵌套深度 |
| p08 | 中文字符串 | 报错信息改英文/拼音（注释可保留中文） |
| p09 | `(vl-load-com)` | 引擎无 VL 入口，需纯 LISP 重写（大工程，先确认） |
| p10 | `vl-catch-all-apply` | 报错包装改用 `progn`+`error` 手写捕获 |
| p11 | `*` 包裹符号 | 全局变量改名（如 `OCS-Version`） |
| p12 | 空局部表 `( / )` | 改为 `( )` 或去掉 |
| p13 | 大整数 `4294967296` / 负数 `-16` | 拆成算术表达式 |

## 5 反馈方式

把以下信息回给开发，即可直接定位并修复：

1. CRLF 变体是否加载成功；
2. `OCS_PROBE` 完整输出（或第一个失败的探针号）；
3. `OCS_BISECT` 完整输出（或第一个失败的部件号）；
4. 目标 CAD 的版本与「关于」信息（用于确认是否为 ZWCAD Classic / "LISP Release 1.0"）。
