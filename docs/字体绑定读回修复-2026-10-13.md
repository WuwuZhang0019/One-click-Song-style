# YJST 字体绑定读回修复

日期：2026-10-13
状态：历史记录；v0.2.3 现场复测失败，已由 v0.2.4 修正

2026-10-13 更新：新日志证明再次写入 FontFile 会清空宋体描述符，下文“重新绑定”及“文件必须非空”的规则已被替换。当前交付与验证见 [宋体描述符兼容修复](宋体描述符兼容修复-2026-10-13.md)。以下保留当时的实现和测试边界。

## 实际现场证据

读取用户提供的 `YJST-20261013.10435800.log` 全部 7144 行，文件为旧 CAD 文本编码。运行对象为未保存的 `Drawing2.dwg`，CAD 报告版本 `23.1s (LMS Tech)`，插件 v0.2.2。

- 第 7102 行进入“分组内字体试写”，说明扫描与修改计划已经完成。日志记录访问了 608 个实体，46 个专业对象列为未覆盖。
- 第 7103–7104 行：写入裸文件名 `simsun.ttc` 返回 `Automation 错误。 文件处理器错误`。
- 第 7105–7106 行：写入 `C:\WINDOWS\Fonts\simsun.ttc` 成功。
- 第 7107–7108 行：`SetFont("SimSun", false, false, 134, 22)` 调用成功。
- 第 7109 行：旧版报告 `FontFile 读回为空，字体未被 CAD 解析`。旧代码把空字符串和读取接口异常合并为同一消息，并且不记录该次读回，因此尚不能证明是文件绑定被清空、英文族名解析失败还是 getter 异常。
- 第 7141–7144 行：撤销及数据核对通过，`recoverFailed=0`，最终为“失败已回滚”。未进入正式样式修改。

## 修复

1. 临时试写与正式修改统一调用 `OCS:writeSongFont`，优先使用 `findfile` 返回的完整路径。
2. `FontFile` 与 `SetFont` 后分别读取字体文件、`GetFont` 的字体族/粗体/斜体/字符集/pitch-family，以及 STYLE 组码 3、4，写入 `FONT_STATE`。
3. 若 `SetFont` 后文件绑定无效，重新写入已选定的字体路径，再完整读回。英文 `SimSun` 无法通过校验时尝试中文“宋体”；不采用新宋体、黑体或其他替代字体。
4. 只有 COM 文件名和 STYLE 组码 3 都指向 `simsun.ttc` / `simsun.ttf`，字体族为宋体，字符集为 134，粗斜体与原始要求一致时才接受。接口读取失败会显示真实接口和错误，不等同于空字符串。
5. 临时试写验证过的族名写入计划，正式修改优先沿用。清空大字体后再次核对；再生后也不能接受已丢失字体文件绑定的样式。
6. 添加 `PLAN_READY`，在计划完成后失败时保留扫描和未覆盖数量，避免将已完成扫描显示为全零。

写入方法仍保持撤销分组、临时样式清理和原数据核对；未移除字体正确性校验。日志中的 `FONT_WRITE_RESULT` 记录最终采用的族名、文件和写入顺序。

## 验证

用此前 v0.2.2 的 GB2312 交付代码，在“只能接受完整路径、SetFont 清空文件绑定”的接口替身中重现了同样的“FontFile 读回为空”和“失败已回滚”。该替身用于验证兼容路径，不是对用户 CAD 内部机制的证明。

执行 `python -X utf8 -m unittest test_lisp_runtime test_diagnostic_logging test_font_binding -q`（工作目录 `tools`），39 项通过。新增 6 项覆盖：

- 试写与正式写入的文件重新绑定，以及二次零修改。
- 中文族名回退和正式样式沿用已验证的族名。
- 始终为空的文件绑定和新宋体替代均必须拒绝并回滚。
- 重新绑定造成粗体丢失时拒绝并回滚。
- FontFile getter 真正报错时保留原始错误。
- 再生后文件绑定丢失时回滚。

静态结构及参数检查通过：204 个顶层表达式、184 个函数、15 个扫描向量。严格 GB2312 构建成功，源码与交付解码后的文本一致。
