# 大图天正标注误分类修复

日期：2026-10-13
状态：v0.2.7 已实现并通过定向回归；原生 CAD 大图待复测

## 现场证据与根因

完整读取用户提供的 `YJST-20261013.11432400.log`，共 74848 行。最后的读取对象为块 `xa0-dxs-pm-b1_TZ` 内的 `TDbDimension2 [1E76]`；第 74844 行调用 `vla-get-TextOverride`，第 74845 行返回 `ActiveX 服务器返回错误: 未知名称: TextOverride`，随后以 `RUN_RESULT`、`RUN_END` 记录预检失败。尚未进入字体写入阶段，因此本次没有已写入修改需要回滚；摘要扫描计数为零是计划尚未成功返回，不能解释为没有扫描对象。

原分类规则只要对象类名含 `dimension` 就作为普通标注处理。天正自定义标注不提供该普通 ActiveX 接口，因而在生成修改计划时中断。现有证据指向对象类型误分类，未表明失败由图纸大小或内存不足导致。

`Drawing3.dxf` 中共有 54 个 `TCH_DIMENSION2`。失败句柄 `1E76` 的公开记录包含 `AcDbEntity`、`TDbCurveEntity`、`TDbDimension2` 子类及图层、几何参数等，但没有完整可用的文字与字体引用结构。因此不能据此声称这些标注已核验为宋体，也不能猜测属性名称后写入。

## 修复

- `OCS:mapClass` 对标注改用原生类名白名单，保留普通对齐、旋转、角度、半径、直径、弧长、坐标标注路径。
- 同时收紧表格、公差和块引用的同类名称片段规则，避免其他专业对象误调用普通接口。
- `TDbDimension2` 保留专业对象身份，进入只读核验报告，结果明确为“无法核验”，附句柄、位置及原因。不调用 `TextOverride`，不写入或炸开天正标注。
- 原有四类天正公开字体核验继续执行。公开核验通过的对象移出未覆盖清单；未知、不一致和其他未适配专业对象继续保留。因此最终仍可能显示“部分完成”。

普通标注 API 的参考依据为 Autodesk 官方 [DimAligned Object](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-ActiveX-Reference/files/GUID-38EB1E39-B67A-4B90-A394-5C3FA260F9F3.htm)。标准类支持接口不能推导出天正自定义类也支持它。

## 验证与边界

1. 新增失败回归，在修改分类前复现预检失败；修复后同一 `TDbDimension2` 不调用 `TextOverride`，错误为零、无法核验为一，原对象保持不变。
2. 明确类名测试验证普通标注、表格、公差、块引用仍被正确分派，名称相似的专业对象不会混入。连同既有日志及天正核验测试，共 16 项通过。
3. 使用日志中实际类型核对分类变化，仅 54 个 `TDbDimension2` 从普通标注改为专业对象；本图普通 `AcDbAlignedDimension` 仍走普通标注路径。
4. 使用 Drawing3 的实际公开 DXF 数据回放源码核验函数，并假设普通样式已成功转换、以 SimSun 参数模拟 GetFont，结果为：天正文字 435、多行文字 19、图名 31、多重引线 83，共 568 项通过；天正标注 54 项无法核验。这仅验证记录适配和分类逻辑，不是原生 CAD 整图执行结果，也不证明实际字体写入成功。
5. 静态检查、严格 GB2312 编码往返和交付文件读取检查通过。源码与文档仍使用 UTF-8。
