# YJST 排查日志与专业引线分类修复

日期：2026-10-13
状态：v0.2.2 日志与分类修复已构建，源码回归通过，目标 CAD 原图待复测

## 本次现场证据

截图中运行的是 v0.2.1，失败发生在第 2 阶段。错误明细明确为 `TDbSymbMultiLeader`、句柄 `1644`、`*Model_Space`，调用 `vla-get-Annotation` 后返回 `ActiveX 服务器返回错误：未知名称: Annotation`。这是不同于上一轮空属性数组的新失败位置。

代码按名称是否包含 `leader` 分派普通引线接口，因而错误处理了这个专业对象。修复改为精确匹配 `AcDbLeader` / `AcDbMLeader` 及既有 `acad_` 别名。没有已验证读取接口的专业引线保留原状，记录对象类型、句柄、图层和所在块，并计入未覆盖；不宣称已转换此类专业对象。

## 日志使用

1. `APPLOAD` 重新加载 `output/gb2312/one-click-simsun.lsp`，确认提示 **v0.2.2**。
2. 执行 `YJST`，无需额外开启开关。命令开始及结束会显示本次 `YJST-*.log` 完整路径。
3. 输入 `YJSTLOG` 可再次显示最近路径。将本次完整日志发回，保留从 `RUN_BEGIN` 到 `RUN_END` 的全部内容；若 CAD 崩溃，保留最后一条已写入的记录。

位置依次尝试 CAD 的 `TEMPPREFIX`、系统 `TEMP`、图纸目录。按日期时间和冲突后缀生成独立文件，不覆盖之前记录。日志不调用 `vl-filename-mktemp`，避免退出 CAD 时被该函数的临时文件清理机制删除。

日志优先使用 UTF-8。旧 AutoLISP 不接受 `open` 的第三个编码参数时，使用双参数接口及引擎原有文本编码，开头明确标记 `CAD-legacy`；不修改 `LISPSYS`。源码和文档为 UTF-8，现有 CAD 加载产物继续严格构建为 GB2312。

每行包括递增序号、CAD 毫秒计时、事件、当前阶段和数据。主要事件：

| 事件 | 用途 |
| --- | --- |
| `RUN_BEGIN` / `ENV` | 插件版本、日期、编码、CAD 版本、产品、图纸路径与文件名、撤销状态 |
| `STAGE` / `ENTITY` | 扫描或读写位置、对象类型、分类、句柄、图层和块上下文 |
| `CALL_BEGIN` / `CALL_OK` / `CALL_ERROR` | 必需接口和写入接口的调用前后及原始错误；短参数保留，长文本只记录长度 |
| `TABLE_CELL` | 表格行列位置；内容读取调用还记录内容索引 |
| `UNSUPPORTED_OBJECT` | 未适配的专业对象及所在位置 |
| `OPTIONAL_PROPERTY_ERROR` | 可选属性读取失败，供排查使用；不单独判定整次命令失败 |
| `ERROR` / `ROLLBACK_BEGIN` / `ROLLBACK_END` / `RECOVERY_RESULT` | 业务失败、是否曾写入、是否尝试撤销、恢复结果 |
| `RUN_RESULT` / `RUN_END` | 完整结构化摘要及最终状态 |

表格的内容索引探测可能记录越界 `CALL_ERROR` 后正常完成枚举，需结合最终状态和错误摘要判断，不能仅搜索某个事件名称判定失败。每条日志写入后关闭文件，因此正常捕获异常或后续崩溃时可保留此前已完成的记录；磁盘或系统崩溃仍可能影响写入。

日志初始化、写入或格式化失败均不替换原始 CAD 错误。最近 40 条保留在内存中，结束时及 `YJSTLOG` 会显示文件写入错误和内存记录。内存记录仅在当前 CAD 会话内有效。
