# YJST 大字体清理顺序修复

日期：2026-10-13
状态：v0.2.5 源码回归通过并构建；目标 CAD 原图待复测

## 现场原因

读取 `YJST-20261013.11053500.log` 共 7251 行，最终“失败已回滚”，恢复失败为 0；本轮扫描 15 个样式、288 个宿主、125 个属性、22 个块，46 个专业对象未覆盖。错误仍在临时试写，正式样式修改数为 0。

- 第 7209 行：SetFont 后，字体族“宋体”、字符集 134、pitch/family 22，文件字段均空，ACAD XData 为 SimSun / 34326；符合描述符绑定验收条件。
- 第 7210 行：`FONT_WRITE_RESULT` 为 `ok T`，证明 v0.2.4 的描述符判定已通过现场试写。
- 第 7215 行：清大字体后，GetFont 字体族变空，字符集变为 1、pitch/family 变为 0，ACAD XData 却仍存在。此时尚未执行 Regen。
- 第 7248–7251 行：撤销、恢复核对和最终日志均完成。

两次读回之间，`verifyBigFontClear` 无条件调用 `substDxf4`，由其执行 entmod；大字体原本就为空也会整条回写 STYLE。正式修改中的 `clearBigFont` 存在相同顺序，因此仅绕过临时试写不足以修复。XData 存在也不能当作 GetFont 正确的替代证据。

## 修复

统一顺序为：保存原粗斜体及参数 → 按需清大字体 → FontFile → SetFont → 只读核对 → Regen 后再核对。

- 将清理放入共用 `writeSongFont` 的开头，覆盖临时试写和正式样式。DXF 4 与 COM BigFontFile 均空时直接跳过 entmod；任一非空则清理，并保留所有应用的 XData。
- 清理失败、entmod 返回 nil、表面成功但读回仍非空时，停止字体写入并进入原有回滚流程。
- 设置宋体后的 `verifyBigFontClear` 与正式样式复核改为只读。缺失 DXF 4 时仍核对 COM；设置字体后若意外重新出现大字体则拒绝，不再用 entmod 破坏已设置的描述符。
- 原粗斜体在清理前保存，避免 entmod 重置描述符后丢失原要求。继续检查字体族、字符集、pitch/family、绑定模式、非字体参数和再生稳定性。
- 添加 `BIGFONT_CLEAR` 的 `skip-empty` / `entmod-before-font` 记录、`BIGFONT_CHECK` 的 DXF/COM 实际值；entmod 纳入原有 CALL_BEGIN / CALL_OK / CALL_ERROR 日志。

未改变专业对象覆盖范围，也未自动保存、提交 Git 或清理既有未提交修改。
